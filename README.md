# UptimePulse — Сервис мониторинга доступности сайтов

Сквозной проект по дисциплине **«Разработка серверных приложений»**.  
**Вариант 23:** Сервис мониторинга доступности сайтов (Uptime Monitor).

---

## 📌 О проекте
**UptimePulse** — платформа для автоматизированного периодического мониторинга работоспособности и производительности веб-ресурсов (сайтов, микросервисов, REST API).

---

## 📂 Структура репозитория (Clean / Layered Architecture)
```text
.
├── cmd/
│   └── app/
│       └── main.py          # Точка входа в приложение (запуск сервера)
├── internal/
│   ├── config/              # Загрузка конфигурации из .env (Config loader)
│   ├── controller/          # Transport / HTTP Handlers (Слой представления)
│   ├── service/             # Business Logic Layer (Слой бизнес-логики)
│   └── repository/          # Data Access Layer (Слой работы с БД)
├── .dockerignore            # Исключения для сборки Docker-образа
├── Dockerfile               # Инструкция сборки легковесного контейнера
├── .env.example             # Шаблон переменных окружения (в Git)
├── .gitignore               # Исключения для Git (скрывает .env, venv, кэш)
├── openapi.yaml             # Спецификация REST API OpenAPI 3.0 (из ЛР2)
├── ARCHITECTURE.md          # Архитектурный отчет (Use Cases, C4, ERD)
├── requirements.txt         # Список зависимостей проекта
└── README.md
```

## 🚀 Запуск проекта

### Вариант А: Запуск в Docker (Лабораторная работа №4)
1. **Сборка Docker-образа:**
   ```bash
   docker build -t uptimepulse-app:latest .
   ```
2. **Запуск контейнера:**
   ```bash
   docker run --name backend-container -d -p 8080:8080 -e HTTP_PORT=8080 uptimepulse-app:latest
   ```
3. **Проверка работоспособности:**
   ```bash
   curl http://localhost:8080/api/v1/health
   ```
4. **Остановка контейнера:**
   ```bash
   docker stop backend-container && docker rm backend-container
   ```

### Вариант Б: Локальный запуск через Python
1. **Установка зависимостей:**
   ```bash
   pip install -r requirements.txt
   ```
2. **Запуск приложения:**
   ```bash
   python cmd/app/main.py
   ```
   Сервер запустится по адресу: `http://localhost:8080`.

## ❓ Ответы на контрольные вопросы (Лабораторная работа №3)

1. **Почему Service Layer не должен знать о деталях HTTP?**  
   Для изоляции бизнес-логики: это позволяет вызывать те же сервисы из консоли (CLI), фоновых воркеров или gRPC без переписывания кода под HTTP.
2. **Опасность хранения секретов в коде?**  
   Утечка паролей в публичный Git-репозиторий и невозможность безопасного деплоя под разные среды (`dev` / `prod`).
3. **Зачем .env.example, если сам .env в .gitignore?**  
   Служит живой документацией и шаблоном для команды и CI/CD без раскрытия реальных паролей.
4. **Для чего используется эндпоинт Health Check?**  
   Для мониторинга и оркестраторов (Kubernetes / Nginx): автоматический перезапуск зависших контейнеров и отключение неработающих узлов из балансировки.
5. **Что такое инверсия зависимостей?**  
   Принцип, по которому модули зависят от абстракций (интерфейсов). Это позволяет подменять базу данных на тестовые моки без изменения логики сервиса.

## ❓ Ответы на контрольные вопросы (Лабораторная работа №4)

1. **Главное отличие виртуальной машины от Docker-контейнера?**  
   ВМ запускает полноценную гостевую ОС со своим ядром через гипервизор (тяжелая, гигабайты памяти, долгий старт). Docker-контейнер использует общее ядро хостовой ОС, изолируя только файловую систему и процессы приложения (легковесный, мегабайты памяти, старт за доли секунды).
2. **Зачем нужен .dockerignore?**  
   Исключает ненужные и секретные файлы из сборки: предотвращает утечку `.env` в образ, исключает локальный кэш `__pycache__` и виртуальные окружения `venv/`, уменьшая размер образа.
3. **Что такое Multi-stage build?**  
   Подход, при котором на первом этапе (Builder) ставятся тяжелые компиляторы и собирается код, а на финальный легковесный образ копируется только готовый бинарник/результат без компиляторов и мусора.
4. **Зачем разделять копирование requirements.txt и остального кода?**  
   Для кэширования слоев Docker. Зависимости меняются редко, а код — постоянно. Сначала скопировав `requirements.txt` и сделав `pip install`, при любых правках в коде Docker пересобирает образ за 1 секунду без повторной загрузки библиотек.
5. **Разница между EXPOSE и флагом -p?**  
   `EXPOSE 8080` — информационная декларация в Dockerfile (документация о том, какой порт слушает приложение). Флаг `-p 8080:8080` в `docker run` реально пробрасывает порт из контейнера наружу в операционную систему хоста.
